## 3. 非法输入（空值 / 超长 / 类型错误 / SQL 注入）

### 3.1 【必修-4】类型错误：非字符串被 `String()` 静默接受（已实测）

`services/notes.js:75-76` 用 `String(input?.title ?? '')` 做转换，**没有类型断言**。实测：

```
POST /api/notes  {"title": {"a": 1}, "content": "x", "category": "learning"}
→ 201 {"ok":true,"data":{"id":"2026-10-14-object-object", …}}
```

`String({a:1})` = `"[object Object]"` → 非空 → **通过校验并入库**，id 变成 `object-object`。
→ **非法类型被静默接受**，是真实的输入校验缺口（数组同理：`String([1,2])` = `"1,2"`）。

### 3.2 空值 / 超长：已覆盖 ✅

| 输入 | 结果 |
|---|---|
| `title: ''` | `400 VALIDATION_FAILED "标题不能为空"` ✅ |
| `title` 200 字 | `400 "标题最多 80 字（当前 200 字）"` ✅ |
| 分类不在白名单 | `400 "分类必须是 … 之一"` ✅ |
| `source_url` 非 http(s) | `400 "来源链接必须以 http:// 或 https:// 开头"` ✅ |
| `tags` 超 10 个 | `400 "标签最多 10 个"` ✅ |

> 缺口：`content` **无上限**（只校验非空）——超大正文可入库。属建议项（§4.4）。

### 3.3 SQL 注入：**安全** ✅（逐处核实）

所有「模板串拼 SQL」的位置，插入的**要么是白名单常量、要么是 `$N` 占位**，用户值一律走参数数组：

| 位置 | 拼接内容 | 来源 | 判定 |
|---|---|---|---|
| `db/notes.js:37` | `${whereSql}` | 由**固定片段** `"category = $N"` / `"… ILIKE $N"` join 而成；值全在 `values[]` | ✅ 安全 |
| `db/notes.js` 列表 | `${EXCERPT_LEN}` | 数字常量 | ✅ 安全 |
| `db/planning.js:23` | `${table}` | `TABLES[type]` **白名单映射**，未命中直接抛 `VALIDATION_FAILED` | ✅ 安全 |
| `db/planning.js:40/41` | `${where(...)}` | 同上，片段化 + `$N` | ✅ 安全 |

**无任何用户输入被直接拼进 SQL 字符串。** 全仓 `query()` 调用均为「SQL + values 数组」两参形式。

### 3.4 命令执行：**安全** ✅

- 无 `eval` / `new Function`（`RegExp.exec` 的 `exec` 命中不算）。
- `asr/audio.py:17` 用 `asyncio.create_subprocess_exec(*cmd)` —— **argv 列表形式、无 shell**，用户提供的 URL 不会进 shell 拼接。
- `asr/scripts/probe_funasr.py` 的 `subprocess.run` 是**开发脚本**，不在请求路径。

### 3.5 其他注入面（顺手核）

- **SSRF**：`services/link.js` 有完整闸门（私网/回环/链路本地/CGNAT/云元数据 + DNS 复验 + 逐跳重定向复验），F14 已实测。✅

## 4. 修复（第二步：按必修项动手）

### 4.1 修复总览

| 必修项 | 问题 | 修法 | 落点 |
|---|---|---|---|
| 必修-1 | body-parser 英文裸透 | `errorHandler` 前置识别 `err.type`：`entity.parse.failed`→400、`entity.too.large`→413，均给中文 | `middleware/errors.js` |
| 必修-2 | `${err.message}` 拼接（中文前缀 + 英文尾串） | 约 14 处调用点全部改**纯中文短句**；原始错误移入 `console.error` | `services/*`、`storage/*` |
| 必修-3 | `admin.js` 裸错零包装（3 处） | 探活/计数失败→中文短句（「连接超时」「统计任务数失败」），原因进日志 | `routes/admin.js` |
| 必修-4 | 类型错误被 `String()` 静默接受 | `validate()` 加类型断言：`title/content/category/source_url` 必须字符串、`tags` 必须数组，否则 400 | `services/notes.js` |
| 建议-5 | SSE 聊天/问答同样透原始错误 | `agent.js` / `kb.js` 的 catch 复用 `userMessage()` + `STATUS_BY_CODE` | `routes/agent.js`、`routes/kb.js` |
| 建议-6 | 任务/笔记里的 `llmError` 落进正文 | 只写「模型服务暂时不可用」，原始错误进日志 | `services/organize.js`、`services/transcribe.js` |

### 4.2 机制：`expose` 标记 + `userMessage()` 单一出口

- `fail(code, message, status, detail)` / `storageError(message, detail)` 构造的错误统一带 `expose:true` → 其人工中文 `message` 可安全透出；`detail` 携带原始 err，仅供服务端日志。
- `middleware/errors.js` 新增 `userMessage(err, code, status)`：有 `expose` → 用 message；否则按 code 查 `FALLBACK_MESSAGE`，再兜底 `GENERIC_4XX/5XX`。
- `STATUS_BY_CODE` 导出，供 SSE 路由复用，保证 HTTP 与流式两条通道**同一口径**。
