║  Day 24 证据①  Bug 复现 —— 提交一个「魔鬼标题」，看服务端返回了什么 ║
║  （等价于 F12 → Network → 该请求 → Response / Preview）              ║
╚══════════════════════════════════════════════════════════════════════╝

接口：POST /api/notes
请求体里 title = 39 个 a + "!!!b"   ← 第 40 个字符恰好会被归一成连字符

──────────────────────────────────────────────────────────────────────
▶ 服务端返回（修复前）
──────────────────────────────────────────────────────────────────────
HTTP/1.1 201 Created
{
  "ok": true,
  "data": {
    "id": "2026-10-14-aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa-",
    "path": "learning/2026-10-14-aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa-.md",
    "hash": "<64位十六进制>"
  }
}

⚠️ 关键错误原文（两行）：
   "id":   "2026-10-14-aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa-"     ← 结尾多一个连字符
   "path": "learning/2026-10-14-aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa-.md"

──────────────────────────────────────────────────────────────────────
▶ 落盘结果（文件名真的带尾巴连字符）
──────────────────────────────────────────────────────────────────────
   "2026-10-14-aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa-.md"

▶ 更糟：同名不同内容再来一条 → 重名兜底是 ${id}-${suffix}，于是：
   "2026-10-14-aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa--2.md"      ← 双连字符
