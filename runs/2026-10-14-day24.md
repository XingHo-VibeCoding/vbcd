## 1. Bug 一句话

**`slugify()` 的截断顺序错了**：它「先去首尾连字符 → 再截断到 40 字符」，
当第 40 个字符恰好是连字符时，截断会把连字符留在末尾，于是资料 id / 文件名尾巴上多个 `-`。

| 项 | 值 |
|---|---|
| 位置 | `server/src/services/notes.js` 的 `slugify()`（第 31–39 行） |
| 触发条件 | 标题归一化后，#40 位置是连字符（即中文/符号等被归一成 `-` 的字符正好落在截断点） |
| 影响 | ① id / 落盘文件名尾部脏连字符；② **重名兜底**（`files.js`：`id = ${note.id}-${suffix}`）产生**双连字符** `...aaaa--2`，越滚越脏 |
| 严重度 | 低（不影响功能正确性，数据可读写）但**会污染 id 形态**，且已能复现 |
| 发现方式 | Day 24 用「刁钻输入」（超长 + 特殊字符）扫接口时命中 |

## 2. 四步证据

### 2.1 ① 复现

```bash
$ node scripts/day24-hunt.mjs      # 用 ~30 组刁钻输入扫接口
── C5 标题超长+特殊 (切 40 字符后尾部连字符)
   status=201 {"ok":true,"data":{"id":"2026-10-14-aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa-", ...}}
                                                                              ↑ 尾部连字符
```

其余 ~29 组输入（空值/纯空格/路径穿越/空字节/tags 越界/参数非法/畸形 id/类型错误）**全部正确处理** —— 只有这一组不走寻常路。这一步很关键：**先把「正常」的排除干净**，剩下的才可疑。

### 2.2 ② 定位

**第一层：锁定函数**（缩小到纯函数，可脱离 HTTP 反复试）

```bash
$ node -e "import('./src/services/notes.js').then(({slugify})=>{ ... })"
len(输入)=43 → slug="aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa-"  长度=40  ⚠️ 尾部连字符
len(输入)=44 → slug="aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"  长度=40  （正常）
len(输入)=41 → slug="aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa-b"  长度=40  （正常）
len(输入)=41 → slug="aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa-"  长度=40  ⚠️ 尾部连字符
```

**第二层：看代码，找到根因**（第 31–39 行原文）

```js
const slug = String(title)
  .trim()
  .toLowerCase()
  .replace(/[^a-z0-9\u4e00-\u9fa5]+/g, '-')   // 归一
  .replace(/^-+|-+$/g, '')                     // ← 先去首尾连字符
  .slice(0, SLUG_MAX)                          // ← 再截断（问题在这）
return slug || 'note'
```

**根因**：`.replace()` 去尾连字符发生在 `.slice()` **之前**。截断时若第 40 位是 `-`，这个 `-` 就**新被留在末尾** —— 前面那次清理白做了。

**第三层：量化验证「顺序」是唯一原因**（不是别的什么）

两种顺序对同一批输入的结果差异 —— **只在边界输入上不同**：

| 输入 | 现状（先清后切） | 改为「先切后清」 |
|---|---|---|
| `'a'×39 + '!!!b'` | `...aaa-` ⚠️ | `...aaa` ✅ |
| `'a'×39 + ' b'` | `...aaa-` ⚠️ | `...aaa` ✅ |
| `'x'×39 + '---y'` | `...xxx-` ⚠️ | `...xxx` ✅ |
| `'a'×40 + '!!!b'` | `...aaa`（本来就对） | `...aaa`（不变） |
| `'正常标题'` / `'!!!'` / `'a/b/c'` / `'../../etc/passwd'` … | 均正常 | **均不变** |

→ 差异**只出现在「截断点落在连字符」**这几例上 ⇒ 病因就是这一个顺序问题，与字符集、编码、路径处理都无关。

### 2.3 ③ 修复

`server/src/services/notes.js`：把两道操作**互换顺序**，并加注释说明为什么顺序有讲究。

```diff
  const slug = String(title)
    .trim()
    .toLowerCase()
    .replace(/[^a-z0-9\u4e00-\u9fa5]+/g, '-')
-   .replace(/^-+|-+$/g, '')
    .slice(0, SLUG_MAX)
+   .replace(/^-+|-+$/g, '')
  return slug || 'note'
```

**为什么这样修而不那样修**（取舍记录）：
- ❌ 不采用「截断后只去掉尾部那一个 `-`」—— 治标；`'x'×39 + '---y'` 截断后可能留多个。
- ❌ 不采用「截断后 `trim('-')`」—— 会连带吃掉中文标题里合法的连字符语义（本例无影响，但规则应统一用 `/^-+|-+$/`，与去首尾口径一致）。
- ✅ 采用「先切后清」—— 最小改动、语义清晰，且**对非边界输入零影响**（上面表格已逐例证明）。

## 3. 今日要掌握的问题：怎么排除其他原因、锁定真因？

四步收敛，每步都**排除掉一大批可能性**：

1. **扫面而非猜** —— 先用 ~30 组刁钻输入把接口扫一遍。结果 29 组正常、1 组异常。**「大多数正常」本身是信息**：说明不是校验层、不是错误处理、不是存储层的普遍问题，而是**某个特定路径**的问题。
2. **把可变因素剥掉** —— 从「HTTP 请求」一路缩到 `slugify()` 这个**纯函数**：同一输入反复试，结果稳定复现（排除「偶发/并发/环境」类原因）。
3. **交叉对照把病因逼到唯一** —— 构造「只有差一个顺序」的两版实现，跑同一批输入：差异**只出现在截断点落在连字符的用例上**。这就把「字符集/编码/路径穿越/长度上限」等**其他候选原因全部排除**，剩下唯一解释：**截断与清理的顺序**。
4. **反证法收尾** —— 修复后**常规输入产出逐例不变**（7/7），且三套回归全绿。若真因找错了，改动必然波及别处 —— 全绿即反向证明「只动了该动的那一处」。

一句话：**先用大范围输入找到异常点，再用「单变量对照」把候选原因一个个排除掉，最后用「不变量」证明只剩那一个原因。**
