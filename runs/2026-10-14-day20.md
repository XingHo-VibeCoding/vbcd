## 3. 跨域诊断（今日主题）

### 3.1 反证：这个项目没有跨域

```
$ curl -sI --noproxy '*' -X OPTIONS \
    -H 'Origin: http://example.com' -H 'Access-Control-Request-Method: GET' \
    http://139.224.192.94/api/health
HTTP/1.1 200 OK
Server: nginx/1.31.6
X-Powered-By: Express
Allow: GET, HEAD
→ 全响应头搜 access-control：无任何命中
```

`OPTIONS` 返回 200 却**没有半条 `Access-Control-Allow-*`**，这不是故障，恰恰是「没有跨域需求」的证据。

### 3.2 为什么不会跨域：三种访问方式全部同源

| 场景 | origin | 请求写法 | 谁转发 |
|---|---|---|---|
| 本地 dev | `localhost:5174` | 相对路径 `/api/...` | Vite（`vite.config.js` 的 `proxy: {'/api': 'http://localhost:3100'}`） |
| 公网 | `139.224.192.94` | 相对路径 `/api/...` | nginx（同 80 端口反代到内网 `server:3000`） |

关键佐证：`web/src/api/client.js` 里所有请求都走**相对路径**（`fetch(path, ...)`），base URL 由浏览器按当前 origin 自动补全。

**跨域是浏览器的限制，不是网络问题**。只要浏览器看到的 origin 只有一个，跨域就不会发生 —— 这叫「用代理规避」，不是「用 CORS 头放行」。

### 3.3 若硬要本地前端直连公网后端：三道关依次失败

```
本地 dev 前端（origin=localhost:5174，目标=139.224.192.94）
  ↓
关① 浏览器跨源判定：协议/主机/端口任一不同即跨源
  ↓
关② OPTIONS 预检被拒：JSON 请求触发预检，响应缺 Access-Control-Allow-Origin
  ↓
关③ 会话 Cookie 不带过去：sid 为 SameSite=Lax（server/src/routes/auth.js:67-72），跨站一律不发送
      注：改 SameSite=None 强制要求 Secure（HTTPS），而公网只有 80、无证书 → 登录态无论如何带不过去
```

### 3.4 判据：怎么认出问题出在哪

**最容易踩的坑**：`client.js` 的 `catch` 把 `fetch` 失败统一转成 `NETWORK` /「无法连接后端服务」。而浏览器因跨域拦截时抛出的错误与真·断网是**同一个 `TypeError`** —— 代码层面分辨不出来，只能看 DevTools：

| 现象 | 指向 |
|---|---|
| Console 出现 `blocked by CORS policy` | 跨域（唯一铁证） |
| Network 多一条 `OPTIONS`，状态 200 但响应缺 `Allow-Origin` | 预检未通过，正式请求未发出 |
| Network 只有 `OPTIONS`、没有真正的 `GET/POST` | 同上，被挡在预检 |
| 请求明明 200，页面仍未登录 | **不是跨域**，是 Cookie 问题 → 看 Application → Cookies 里 `sid` 在不在、SameSite 是什么 |
