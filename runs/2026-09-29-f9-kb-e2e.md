## 2. 三个接口的实测结果

### 2.1 建增量索引 `POST /api/kb/index`

```bash
curl -s -X POST http://localhost/api/kb/index -H 'Content-Type: application/json' -d '{}'
```

```json
{"ok":true,"data":{"added":1,"updated":0,"removed":1,"unchanged":4,"chunks":3}}
```

结论：✅ 未返回 `KB_NOT_CONFIGURED` → Chroma 可达、embedding 调用成功；增量清单（`data/.kb-manifest.json`）按指纹正确识别「新增 1 / 删除 1 / 未变 4」。

### 2.2 非流式问答 `POST /api/kb/query`

```bash
curl -s -X POST http://localhost/api/kb/query -H 'Content-Type: application/json' \
  -d '{"q":"buddy 的资料存在哪个目录？","k":3}'
```

返回（截断）：

```json
{"ok":true,"data":{
  "answer":"资料库里没有相关内容。\n\n给出的三份资料分别讲的是：…三份资料都没有出现\"buddy\"，也没有提到任何资料存放目录的信息，因此无法回答…",
  "sources":[
    {"note_id":"2026-09-19-prd-review","title":"PRD 首轮 AI 自检抓出的 4 个问题","path":"work/2026-09-19-prd-review.md","chunk_index":0,"score":1.3738647},
    {"note_id":"2026-09-19-proxy-502","title":"推送 502 的根因：失效代理","path":"work/2026-09-19-proxy-502.md","chunk_index":0,"score":0.69…}
  ]}}
```

结论：✅ 三件事同时成立——① 检索层回了带 `score` 的来源并给出 `path`；② 生成层基于检索内容作答；③ **拒答而不是编造**（资料里确实没有该信息）。第 ③ 点是对 RAG 最有价值的行为，本次拿到了。

## 4. 隐私模式（`AUTH_ENABLED=1`）下的 KB 接口鉴权（2026-09-29 补验）

公开模式测过不代表隐私模式没问题，故另起一份服务实测。

### 4.1 测试环境：`docker compose run`（不是 `docker run`）

```bash
cd /home/bird/work/vbcd
H=$(cd server && node scripts/hash-password.js "priv-test-pw" | head -1)
docker compose run -d --name buddy-priv-run --publish 127.0.0.1:3195:3000 \
  -e AUTH_ENABLED=1 -e PASSWORD_HASH="$H" -e ASR_SERVICE_URL= -e ASR_SERVICE_TOKEN= server
```

> ⚠️ **为什么必须用 `docker compose run` 而不是 `docker run --env-file`**：`docker run` **不剥行内注释**，会把 `server/.env` 里 `KEY=value   # 中文注释` 的注释一起当值。实测后果：`OPENAI_API_KEY` 长度 **117 → 165**，`Authorization: Bearer …# 可换…` 里出现 >255 的字符，Node `fetch` 报 `Cannot convert argument to a ByteString … character at index 145 has a value of 21487`（21487 = 「可」）。**这曾被我误判为代码 bug**，实为测试夹具的坑；已作为踩坑行写进 `RUN.md` 8.7。

### 4.2 鉴权矩阵（全部实测）

| # | 请求 | 结果 |
|---|---|---|
| ① | `GET /api/health` | `auth_enabled:true` |
| ② | `GET /api/notes`（无 cookie） | **401** |
| ③ | `POST /api/kb/query`（无 cookie） | **401 `AUTH_REQUIRED`「请先登录」** ← 本次要补的缺口 |
| ④ | `GET /api/kb/stream`（无 cookie） | **401** |
| ⑤ | `POST /api/login`（错口令） | **401 `AUTH_FAILED`「口令错误」** |
| ⑥ | `POST /api/login`（对口令） | **200** + 下发会话 cookie |
| ⑦ | `GET /api/notes`（带 cookie） | **200** |
| ⑧ | `POST /api/kb/query`（带 cookie） | **200**，拿到真实答案（代理端口失效 → 502，与资料一致） |
| ⑨ | `POST /api/logout` | **204** |
| ⑩ | 登出后旧 cookie 再问 KB | **401 `AUTH_REQUIRED`** |

结论：✅ **KB 三个接口在隐私模式下同样受 `requireAuth` 保护**，会话生命周期（登录 → 带 cookie 可用 → 登出后立即失效）完整。测试容器已 `docker rm -f`。
