## 2. 三个接口的实测结果

### 2.1 建增量索引 `POST /api/kb/index`

```bash
curl -s -X POST http://localhost/api/kb/index -H 'Content-Type: application/json' -d '{}'
```

```json
{"ok":true,"data":{"added":1,"updated":0,"removed":1,"unchanged":4,"chunks":3}}
```

结论：✅ 未返回 `KB_NOT_CONFIGURED` → Chroma 可达、embedding 调用成功；增量清单（`data/.kb-manifest.json`）按指纹正确识别「新增 1 / 删除 1 / 未变 4」。

### 2.2 非流式问答 `POST /api/kb/query`

```bash
curl -s -X POST http://localhost/api/kb/query -H 'Content-Type: application/json' \
  -d '{"q":"buddy 的资料存在哪个目录？","k":3}'
```

返回（截断）：

```json
{"ok":true,"data":{
  "answer":"资料库里没有相关内容。\n\n给出的三份资料分别讲的是：…三份资料都没有出现\"buddy\"，也没有提到任何资料存放目录的信息，因此无法回答…",
  "sources":[
    {"note_id":"2026-09-19-prd-review","title":"PRD 首轮 AI 自检抓出的 4 个问题","path":"work/2026-09-19-prd-review.md","chunk_index":0,"score":1.3738647},
    {"note_id":"2026-09-19-proxy-502","title":"推送 502 的根因：失效代理","path":"work/2026-09-19-proxy-502.md","chunk_index":0,"score":0.69…}
  ]}}
```

结论：✅ 三件事同时成立——① 检索层回了带 `score` 的来源并给出 `path`；② 生成层基于检索内容作答；③ **拒答而不是编造**（资料里确实没有该信息）。第 ③ 点是对 RAG 最有价值的行为，本次拿到了。

### 2.3 SSE 流式 `GET /api/kb/stream`

```bash
curl -sN "http://localhost/api/kb/stream?q=推送%20502%20的原因是什么&k=2"
```

事件流（截断）：

```
event: sources
data: {"sources":[{"note_id":"2026-09-19-proxy-502",...,"score":0.69678074},
                  {"note_id":"2026-09-19-wsl-env",...,"score":1.3319207}]}

event: token
data: {"text":"推送 "}
event: token
data: {"text":"502 的原因："}
event: token
data: {"text":"环境变量里的"}
event: token
data: {"text":"代理端口"}
...
```

结论：✅ 先 `sources` 后逐 token；内容与 `data/work/2026-09-19-proxy-502.md` 一致（代理端口无人监听 → `CONNECT tunnel failed 502` / `TLS handshake failed`），**无幻觉**。
