## §3 演示提纲（四段结构）

> 用途：3 分钟演示 / 答辩。四段：**用户问题 → 核心流程 → 提示词改写 → 验证方式**。
> 「完整走通一遍」已由 §1.4 的 API 实走完成（打开 → 读 → 写 → 读回 → 回滚）。

### 3.1 用户问题（为什么做）

我要解决的**不是「记笔记不够快」，而是「AI 助手不会成长」**（节选自 `research.md` §1 / `PRD.md` §1）：

1. AI 每次会话都**失忆** —— 纠正过的规则下次照犯；
2. 资料散落各处，想让 AI 按**我自己的资料**回答却做不到；主流产品的记忆**不可查看、不可编辑、不可迁移**；
3. 笔记缺的不是工具，是**可检索的组织方式**；
4. 「多端同步 + 免费」没人做好 —— 桌面优先、手机将就；
5. 从**手机**发起任务、确认操作不方便，多数方案要求桌面窗口常开；
6. 只有「记录型」产品，没有「**经我确认后替我行动**」的行动型助手。

**一句话**：buddy = 一个**资料在我手里、手机就能用、动手前先问我**的会成长的助手。

### 3.2 核心流程（演示主线，约 2 分钟）

```
记一条           网页 → 标题 + 正文 → 保存         → POST /api/notes          落 PostgreSQL（落点自适应：无库则落文件）
查回来           关键词 → 列表 → 点开原文          → GET /api/notes          打开列表页索引自动重建
发起任务         手机浏览器提交任务                 → POST /api/tasks         状态 待办/进行中/完成
先问我再动手     删除等高风险动作 → 确认页 → 执行   → PATCH /api/tasks/:id    428 闸门在后端强制
能力组合①        贴链接 → 抓正文 → 整理 → 归档      → POST /api/tasks (organize)
能力组合②        贴视频链接 → 转写 → 整理 → 归档    → POST /api/tasks (transcribe_url) → asr/ 微服务
问它             用我自己的资料问答，答完给来源     → POST /api/kb/query / GET /api/kb/stream
看见             首页一屏给出：资料数 / 今日 / 计划 → GET /api/home
```

**演示只走最稳的三段**：① 首页打开有真实数据 → ② 归档写一条 → ③ 首页计数跟着变（本次已实测，见 §1.4）。

### 3.3 提示词改写（我用 AI 编程时改了什么）

**要点**：把「一句模糊的大需求」改写成「**一次一步、带完成标准与验证方式**的小指令」——这是本项目能持续交付的关键。

| 场景 | 改写前（模糊，返工多） | 改写后（可执行，一次过） |
|---|---|---|
| 交付节奏 | 「帮我做个个人助手」 | 每日清单式：限定范围 + 明确「今日不做」+ 完成标准 + 要交什么截图 |
| 推进方式 | 「你继续做完」 | 「**一次只做一个步骤**；做完说清：做了什么 / 改了哪些文件 / 怎么验证；等我说『进入下一板块』」 |

**一句话**：不是「让 AI 更聪明」，而是**把需求写成 AI 不会跑偏的形状**。
