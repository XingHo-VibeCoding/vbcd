# backend-verify 首次调用留证（Day 22）

日期：2026-10-14 ｜ 调用者：AI（Day 22 板块①–③ 后端接口验证）

## 背景

Day 22 清单为「PATCH / DELETE 上线并验证 + 四类操作闭环」。摸底发现两接口**已实现**（10-11 后台板块⑥），
故本日转为**验证**。验证过程中固化了这套「隔离实例 + 真实 HTTP」套路，本文件是它的首次留证。

## 本次实际用法（与 SKILL §2 一致）

- 脚本：`server/scripts/day22-verify.mjs`
- 起法：进程内 `createApp().listen(0, '127.0.0.1')`；`DATA_DIR = mkdtemp()`；`AUTH_ENABLED='0'`；`DATABASE_URL=''`（文件模式）
- 打法：`fetch` 真实 HTTP，断言状态码 + 错误码 + 数据变化
- 收尾：`finally` 里 `appServer.close()` + `rm -rf` 临时目录

## 结果

**12 项断言全绿**：
- 板块① PATCH：改之前/之后对照（三处字段变、`created_at` 保留、`updated_at` 跨秒更新）、`400`、`404`
- 板块② DELETE：`GET /:id` → `404`、列表消失、重复删 `404`；实际状态码 `200`
- 板块③ 闭环：`CREATE(201) → READ(200) → UPDATE(200) → READ(200) → DELETE(200) → READ(404)`

## 本 Skill 由此固化的重要踩坑（本次亲历）

1. **临时目录不能用 `/tmp`**：先生成 `/tmp/day22-verify/` → 前台 `ls`/`curl` 全看不到（sandbox 隔离）；改用 `mkdtemp()` 后正常。
2. **`&` 起的后台服务会被回收**：`node src/index.js &` 后下一条命令 `curl` 报 `Connection refused`，`ps` 查不到进程 → 必须进程内起服务。（对应 SKILL §5 前两行）
