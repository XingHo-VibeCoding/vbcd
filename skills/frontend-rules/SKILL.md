# buddy 前端样式规则：检查清单

本 Skill 是**全站通用**的（不是某个页面专用）。它只写「怎么查、查什么、查完怎么留证」，
**不复制任何具体色值或尺寸值**——那些的唯一定义处见第 1 节列表，两处写值必然漂移。

## 0. 一句话

检查这个项目里**所有前端页面的样式改动**：字号/间距/圆角只走规定的 token 档位、颜色只在一处定义
且改值后对比度复核达标、交互态与移动端触控尺寸齐备、可访问性不倒退，并且**改前先读规则、改后必跑验证命令**。

## 1. 规则真值在哪（动手前先读，不要凭记忆）

| 要知道什么 | 去读哪 |
|---|---|
| 颜色 token（浅色 / 深色两套同名） | `web/src/styles.css` 顶部的 `:root` 与 `:root[data-theme='dark']` |
| 字号 / 间距 / 圆角阶梯 | 同上（`--fs-1..7`、`--sp-1..7`、`--radius-sm|--radius|--radius-lg`） |
| 主题机制与边界（F10） | `SPEC.md` §1.1 前端主题 |
| 交互反馈三档与提示条规格 | `SPEC.md` §5.3.1 |
| 移动端与对比度的验收口径 | `PRD.md` 的 F7 / F10 验收标准 |
| 每条规则**为什么存在**（修订来源） | `AGENTS.md` §4 的 Day 9 / F10 / F11 / Day 11 条目（含注释里的 P1–P5 编号） |

各条规则的编号沿用既有口径：**P1 信息层级、P2 字体、P3 颜色、P4 间距与对齐、P5 状态与移动端**。

## 2. 六类检查清单

### 2.1 页面层级（P1）

- [ ] 所有 `font-size` 取自 `--fs-1..7` 七档，**不出现 12px 及以下**（本项目已取消 12px 档，最小 13px）。
      **唯一例外**：720px 以下输入类控件的 `16px`（见 2.4）——那是防 iOS 聚焦缩放的硬要求，不是层级档，不适用本行；
- [ ] 层级顺序完整、单调：页面主标题 > 详情页标题（与正文 `h1` **脱钩**，不共用一档）> 卡片标题 ≈ Markdown `h1` > 列表项标题 ≈ Markdown `h2` > 正文基准 > 提示 / 按钮 / 徽章 > 元信息 / 标签；
- [ ] 相邻两档字号差 **≥2px**（不出现 15/16 这种肉眼分不开的搭配）；
- [ ] 正文基准档是全局默认，不要用某个组件单独撑大或缩小；
- [ ] 层级靠字号+字重表达，不靠随意加粗（见 2.2）。

### 2.2 颜色和字体（P2 / P3）

- [ ] **颜色只有一处定义**：组件规则里零硬编码色值；需要新颜色时，先按语义加 token，**浅色与深色两套都加**；
- [ ] 状态色（成功 / 警示 / 危险 / 禁用 / hover）同样必须是 token，不许写死在组件规则里；
- [ ] 改成任何色值后，按 **WCAG 相对亮度公式**复核对比度：正文、次要文字、徽章、按钮文字、禁用态文字 **≥ 4.5:1**；仅作为 UI 边界的线条（如 `--warn-line`）**≥ 3:1**；**两套主题都要算**，不许凭眼睛调；
- [ ] 字重不写 `500`（本机字体栈里微软雅黑没有 500 档，属虚标）——用 400 / 600 / 700；
- [ ] 数字对齐处用 `tabular-nums`，避免表格与日期跳字宽；
- [ ] 深色下的原生控件跟随主题（由 `color-scheme` 负责，不要手写覆盖滚动条 / select 下拉）。

### 2.3 卡片与按钮（P4 / P5）

- [ ] 间距取自 `--sp-1..7` 七档，不出现裸值；尺寸类（`min-height` / `max-width` / 宽高）优先取 4 的倍数；
- [ ] 允许的例外**只有两类，且必须在行内注释写明理由**：
      ① **文字级微调**：徽章与行内 `code` 的 1px 纵向内衬；
      ② **几何 / 网格计算值**：贡献热力图的 10px 方格、头像与圆点的 `border-radius: 50%`、10px 方格的 2px 圆角——这类值由图形尺寸推导，不是间距阶梯语义；
      （没有注释的裸值一律按违规处理）；
- [ ] 圆角取自 `--radius-sm` / `--radius` / `--radius-lg`，例外同上第 ②类；
- [ ] **左基准对齐**：同一列的卡片与列表项内容左缩进一致；工具栏里输入框与下拉框左缩进一致；
- [ ] 可点元素必须有 hover 态（主按钮、幽灵按钮、危险按钮各有专值），不只靠光标形状；
- [ ] 禁用态必须可见且文字对比度达标（不是单纯调低透明度）；
- [ ] **零动画**：不新增 `transition` / `animation` / `@keyframes`（使用者 2026-09-27 明确要求全站无动画）；
- [ ] 按下应有**即时可见**的变化；操作结果按 `SPEC.md` §5.3.1 的三档反馈选择（即时态 / 短暂提示 / 结果留痕），提示条走既有 `Toast` 组件，不新建第二套。

### 2.4 移动端适配（P5）

- [ ] 断点只用 **720px 与 480px** 两档，与既有 `@media` 块对齐，不新增第三档；
- [ ] 720px 下所有可点元素（按钮、页签、列表项链接、切换组）`min-height: 44px`；
- [ ] 720px 下输入类控件（`input` / `select` / `textarea` / 编辑区）字号 **16px**，防 iOS 聚焦自动缩放；
- [ ] 480px 下工具栏与表单行允许换行，不被挤扁；
- [ ] 页面整体无横向滚动（`overflow-x: clip` 兜底）；
- [ ] **375px 视口**走一遍：无溢出、无遮挡、可点区域够大；
- [ ] 分栏布局在窄屏降级为单列或页签切换，而不是横向塞满。

### 2.5 可访问性（并入上面各条，这里集中列一次）

- [ ] 焦点可见：全站统一 `:focus-visible` 焦点环只有一处定义，`Tab` 走一遍每一站都能看见；
- [ ] 交互控件优先用原生 `button` / `a` / `input`，`Enter` 与 `Space` 行为与鼠标点击一致；
- [ ] 提示类容器用 `role="status"` + `aria-live="polite"`，且**容器常驻 DOM**（若随内容一起卸载，很多读屏不会播报）；
- [ ] 切换类控件用 `aria-pressed` / 语义属性表达当前状态，不只靠颜色；
- [ ] 状态不只靠颜色区分（徽章要有文字）；
- [ ] 装饰元素不进入读屏（`aria-hidden` 或空 `alt`）。

## 3. 修改前检查（动手前逐条问自己，答不上就回去读第 1 节的文件）

1. 我要写的这个值，**属于哪一档 token**？没有对应档位 → 先提出「要不要加一档」，**不新建裸值**；
2. 会不会引入硬编码色值？（包括状态色）
3. 是否**只改样式、功能零改动**？CSS-only 优先；
4. 浅色与深色**两套是否都成立**？
5. 会不会新增动画 / 过渡？（不该有）
6. 会不会动到项目结构（新增目录或文件）？会的话**先报备再动**；
7. 改完记得提醒使用者**刷新浏览器**看效果。

## 4. 修改后验证（必跑，输出写进调用记录）

```bash
cd web && npm run build                                          # ① 必须通过
grep -n "transition\|animation\|@keyframes" src/styles.css        # ② 期望【无输出】
grep -nE "#[0-9a-fA-F]{3,8}|rgba?\(" src/styles.css                # ③ 逐个确认只出现在 token 定义块里
```

- ④ 只要动过色值：用脚本按 WCAG 相对亮度公式核算**两套主题**的对比度，记录达标配对数（不达标即视为未完成）；
- ⑤ 窄屏自查 720px / 480px / 375px；键盘 `Tab` 走一遍焦点环；
- ⑥ 页面**最终视觉效果由使用者刷新浏览器确认**——本项目的 AI 运行纪律规定：不调用浏览器工具、不调用视觉模型核对渲染结果（仅 `compile` 或使用者主动发图时例外）。

## 5. 调用方式与留证

- **手动强制调用**：在 pi 里输入 `/skill:frontend-rules`（改过本文件后先 `/reload`）；
- **自动匹配**：由本文件 frontmatter 的 `description` 触发加载；
- **每次真实调用留一份记录**：`skills/frontend-rules/runs/YYYY-MM-DD-<场景>.md`，内容必须含
  **调用方式 · 检查对象 · 逐条结论（通过 / 不适用 / 发现问题）· 跑过的命令与原始输出 · 未做项与原因**；
- 发现不合规之处：**先报告、等使用者决定**是否修，不顺手改（会越出当天任务边界）。

## 6. 不做什么

- 不做视觉审美评审，也不看渲染截图；
- 不改功能逻辑、不新增接口（那是别的 Skill 与别的天的事）；
- 不把 token 的具体数值抄进本文件；
- 不在没有使用者确认时改动 `web/src/styles.css`。
